## פעולות חשבון נדרשות
GitHub > targilim > Settings > Secrets and variables > Actions:
1. GEMINI_API_KEY: מפתח Gemini API מורשה, עם בדיקת מכסות/עלויות. קיימת גם אפשרות Google Cloud שדורשת תכנון הרשאות נפרד.
2. ANTHROPIC_API_KEY או CLAUDE_CODE_OAUTH_TOKEN: לבחור אחד בלבד, לפי תנאי הספק.
3. OPENAI_API_KEY: מפתח OpenAI Platform בפרויקט ייעודי, נפרד ממנוי ChatGPT.

אין להעתיק סודות ל-Issue, לשיחה, ל-commit או לקובץ רגיל. אין צורך להגדיר Secret כדי להריץ את בדיקות ה-PR. אימות זהות לחשבונות והמגבלות הכספיות מחייבים פעולת בעלים מאושרת.

## מגבלות
- כל הסוכנים בהרצת ה-Smoke: GitHub contents:read בלבד, ללא git push, merge או deploy.
- Claude Code: שני סבבים ותקרת הוצאה משוערת של $0.50. אין בכך התחייבות שתקרת החשבון אינה יכולה להיחרג.
- Gemini: רק כלי קריאה; לכל היותר ארבעה סבבי שיחה לפי תצורת CLI; הגדרת overageStrategy=never אינה מגבלת חיוב חשבונאית מוחלטת.
- Codex: read-only ו-low effort; אין תקרת דולר קשיחה ברמת ה-workflow.
- זמן הרצה מרבי: 10 דקות לספק; concurrency יחיד. ספקים לא מאומתים אינם מופעלים אוטומטית.
- חובה להגביל שימוש ברמת חשבון ספק. ללא הרשאות ותקציב מאומתים: STOP.

## חזרה ל־GPT עם ראיות מהסוכנים
אחרי Smoke מוצלח של ספק יחיד, ה־workflow יכתוב בדוח GitHub Actions וב־job log את הסימון AI_LAB_REPORT_START ואחריו דוח תוחם עם ספק, SHA, מזהה ריצה וטקסט תוצאה מקוצר. GPT יוכל לקרוא את יומן הריצה דרך GitHub ולהציג את הממצאים בשיחה אחת, אך מדובר **בתשובת מודל לא מאומתת על ידי אדם** ולא באישור נכונות מתמטית. תוכן שחורג מ־2,400 תווים נקטע, ונעשה סינון בסיסי של מחרוזות שנראות כמו מפתחות; אין לכך הבטחת DLP מלאה. אין להציג נתון על הוצאה בפועל לפני בדיקת חשבון הספק.

המידע מתווסף רק לאחר קריאת מודל שהופעלה כדין, לא בבדיקת PR רגילה. קריאת מודל תישאר חסומה ללא Secret ואישור בעלים בהתאם להוראות הקוד.

## AI Gateway API — אימות אמיתי והחסמים שנמצאו (16.11.2026)
- הוגדר ניסיון OIDC בפרויקט Vercel החדש, אך **בדיקת פונקציית השרת האמיתית החזירה GATEWAY_AUTH_NOT_AVAILABLE**. אין לטעון ש־OIDC עובד או שהמודלים מחוברים.
- הוקמה פונקציית GET לקריאה בלבד בכתובת [AI readiness](https://targilim-ai-lab.vercel.app/api/ai-readiness). פונקציה זו מחזירה סטטוס בלבד; היא אינה מפעילה מודלים או מגלה אסימונים. קוד המקור `lab/api/ai-readiness.js` ובדיקות `tools/ai-lab-gateway-readiness.test.mjs`.
- קיים מסלול חלופי של `AI_GATEWAY_API_KEY` בפרויקט Vercel, אך **לא נוצר ולא הוגדר בו מפתח בפועל**. כל מפתח חייב להישמר ב־Vercel Environment Variables במצב Sensitive/Encrypted ולא בקוד/שיחה.
- השאילתה לאימות הוצאות AI Gateway בחשבון המעבדה החזירה 403; לא ניתן לקבוע מהו תקציב החשבון או היתרה. לפני ניסוי חי יחיד יש לאמת חשבון משלם/קרדיטים ולהגדיר תקציב פרויקט או מפתח דרך כלי Vercel המורשים. חשוב: תקרת AI Gateway היא soft cap — בקשה חוצה עשויה להסתיים לפני חסימה; תעבורת BYOK אינה נספרת תחת אותה מכסה.
- הפריסה של מסך הבקרה עודכנה עם לחצן בדיקת API ומצב התיקון הפדגוגי ב־PR #69. האתר הנפרד [targilim-ai-lab.vercel.app](https://targilim-ai-lab.vercel.app/) וה־API אומתו ב־HTTP 200. `main` והמחולל החי לא השתנו.
- PR #69, המבוסס על #58, תיקן הסתרת סימוני MCQ בתצוגת תלמיד והדפסת פתרונות סגורים. שתי בדיקות באג בתיקון נלכדו ותוקנו בזמן אמת; `npm run verify:deep` עבר בענן ב־SHA `7a1fe0784f40c918b565478e2ccf1279def02912`. נדרש CI על SHA מועמד למיזוג ואישור בעלים.

## תיקון בדיקת OIDC וסטטוס CI — 16.11.2026
- תוקן שגוי בבדיקה הקודמת: לפי Vercel `VERCEL_OIDC_TOKEN` קיים בזמן build ואילו בזמן ריצת Function האסימון מועבר בכותרת `x-vercel-oidc-token` של ה־Request. הפונקציה `lab/api/ai-readiness.js` בודקת כעת גם את הכותרת הזאת.
- אסימון שנצפה בכותרת **אינו ראיה בפני עצמו שהוא חתום ותקין או שה־AI Gateway מורשה לחייב**; אין להשתמש בתוצאת הכותרת כשער הרשאה. שום אסימון או מפתח אינו מוחזר דרך ה־API.
- בדיקות רגרסיה מוודאות שהכותרת מזוהה ללא הדלפתה, גם עם אותיות גדולות/קטנות, ומסרבים להסיק תקציב או חיוב.
- כפתור רענון בדיקות GitHub במסך הבקרה אינו נעול עוד ל־SHA ישן; הוא מחפש קודם את ה־SHA הנוכחי של PR #63 ומחזיר במפורש אם אין לו הרשאת קריאה ל־API הציבורי. תוצאות ברירת המחדל הן היסטוריות בלבד.
- **אין לבצע קריאות מודלים או לחשוף את אסימון OIDC בצד הלקוח.** אימות Gateway ובקרת תקציב נדרשים בנפרד.

## אימות Gateway דרך נקודת קרדיטים (16.11.2026)
- תוקן זיהוי OIDC בזמן ריצת Vercel Function: כותרת `x-vercel-oidc-token` נמצאה, אך קיום כותרת לבדו **אינו** אימות הרשאה.
- נוסף מסלול GET יזום בלבד: `/api/ai-readiness?verify=credits`. השרת מוסר את האסימון רק בבקשת GET אחת ל-`https://ai-gateway.vercel.sh/v1/credits`, ללא קריאת מודל, ללא החזרת תוכן תגובת הקרדיטים, ללא החזרת מפתח, עם timeout 5 שניות וללא retry.
- בבדיקת השרת החיה (Deployment `dpl_4cTkQbZw4X5qf6rcWi462AtCj4eH`, כתובת קבועה `https://targilim-ai-lab.vercel.app/api/ai-readiness?verify=credits`) התקבל **HTTP 200**, `gateway_probe_status: AUTHENTICATED_CREDITS_ENDPOINT`, `gateway_account_verified: true`, `gateway_budget_verified: false`, `model_calls_performed: 0`.
- המשמעות: **הרשאת OIDC ל־AI Gateway אומתה לנתיב המידע בלבד**, אך אין עדיין תקרת הוצאה/יתרת חשבון מאומתת לשימוש במודלים. ה־API לא מספק הוכחת תקציב וכניסה לתצוגת הקרדיטים אינה הרשאה לבצע חיוב.
- נתיב קוד: `lab/api/ai-readiness.js`. בדיקות: `tools/ai-lab-gateway-readiness.test.mjs`, כולל 401/403/402, דרישת GET, איסור הדלפת אסימון או סכום, וריסון כשלי רשת. `node --test` עבר במכונת Vercel Sandbox ב־SHA `24ec947a037fe29d21e692a4af5ef366dbb8d839`, ו־`npm run verify:deep` באותו SHA עבר.
- התקציב של AI Gateway חייב להיקבע בממשק החשבון/CLI בהרשאת בעלים; ב־Vercel API לבדיקת שימוש התקבלה קודם שגיאת 403. אל תיצור או תגדיל תקציב, אל תגדיר auto-top-up, אל תפנה ל־BYOK ואל תבצע בקשות inference ללא הרשאה מפורשת. תקרות Gateway הן soft caps.
- אין מיזוג PR #63 או פריסה למחולל התרגילים; הפריסה שבוצעה היא **מסך בקרה נפרד**.
